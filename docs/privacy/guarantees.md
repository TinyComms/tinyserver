# The matrix of privacy guarantees

This is the reference for what TinyComms, run as a managed service (TinyCloud), can and cannot promise about privacy. Every other document in this directory feeds it. Each guarantee has an ID, a status and an **Evidence** cell that names a test, a file, or says "not verified". If a row has no test, it says so.

State described: tinyserver `origin/main` at `c4ae28b` (#20: abuse reports, operator suspension and legal hold, tenants, encrypted backups) plus the documents in this directory, re-checked by reading on 2026-11-01, then updated for #23 (the server side of text and attachment E2EE, migrations `0020` to `0023`) with its tests run; tinyclient `26916e9` read only. The TinyCloud control plane (provisioning, billing, staff tooling) is not in this repository, and nothing here describes it as built. **Text and attachment E2EE: the server side is implemented and tested; the client side is on tinyclient's `hardening/e2ee-core` branch, not in `26916e9`, and not verified here** ([`../e2ee-text.md`](../e2ee-text.md)). A category 1 row holds against a hostile operator only if the client does its part, so rows that depend on the client say **client: not verified** and must not be advertised as available. Section 8 lists what is still open.

## 0. How to read this

**The five categories** (used the same way in every document in this directory):

| # | Category | What it means | Strength |
|---|---|---|---|
| 1 | Information the server **cryptographically cannot decrypt** | The server holds ciphertext and no key. No operator action changes that | Enforced by cryptography. Holds against the operator, the host and a court order served on them (they have nothing to read) |
| 2 | Information whose access is **operationally restricted** | The server holds it in a readable form. Software and deployment choices restrict who can read it. Someone with enough access (the database owner role, host root, a compromised process) can read it | Enforced by code and configuration, not by cryptography. Honest wording must say "restricted", never "cannot" |
| 3 | Information the provider **chooses not to collect** | The product has no field, table or log line for it | A design choice. It holds as long as the code is the code that runs; an operator could add collection |
| 4 | Information **necessarily visible to infrastructure providers** | Cloudflare, the hosting provider and the network see it because of where they sit | Cannot be removed by any change to tinyserver or tinyclient |
| 5 | Information **retained for billing, security or compliance** | Kept on purpose, for a stated reason and a time | A policy and a record, which this table lists so it can be bounded |

**Status words:** *Implemented, tested* (a test named in Evidence fails if the property breaks); *Implemented* (code does it, no test asserts it); *Designed* (written down, not built); *In progress* (being built elsewhere, not merged); *Not done*; *Not verified*.

**Evidence** is a test (path and name), a file, a document, or "not verified". A claim backed only by a document in this repository is as good as that document; where it was cross-checked against code, it says so.

What category 1 does **not** contain: any existing text, any attachment in a plaintext conversation, calls in transport-only mode, call and conversation **metadata** (who, when, how big, who is in each group, which devices a person has), reactions (plaintext even in an encrypted conversation), names, topics.

The operator's `tinyserver operator hold` keeps every resolved report and makes `operator.sh` refuse `delete` and `restore` (`0016_operator.sql`; `deploy/tests/hooks.sh`). **Not preserved**: the message a report names (a member can still delete it; the report keeps only its id, which goes null if the row goes), any account (`DELETE /v1/me` still runs under a hold), channels, uploads. No copy is made to a separate access-controlled store ([`findings.md`](findings.md) N12) |
| G5.10 | Backups: database dump, uploads, Pocket ID data, secrets | Recovery, moving a community | Wherever and for as long as the operator keeps the file; no schedule or retention exists | Implemented, tested (shell check, not in CI): `deploy/tenant/operator.sh backup`, `export`, `restore`, encrypted with age to the operator's recipients and to the tenant's own key if `keygen` made one; `deploy/tests/hooks.sh`. A restore brings back what was deleted since (N11). The tenant's key is on the same host until moved ([`findings.md`](findings.md) S11) |
| G5.11 | Postgres WAL and dead rows; Cloudflare logs; hosting provider logs | Operation | Their policies | Not reviewed |
| G5.12 | A ledger of deleted account ids to replay after a restore | Honour erasure after restore | Not defined | **Not built**; `restore` replays nothing ([`findings.md`](findings.md) N11) |
| G5.13 | `operator_state` and `operator_events`: the mode, the notice, whether a hold is on, and every suspend, resume, hold and release with its reason | The operator's own record | Indefinitely; nothing prunes `operator_events` | Implemented (`0016_operator.sql`). The runtime role can read `operator_state` only, never `operator_events`. No actor is recorded |

## 7. What must NOT be claimed

| Claim | Why it is false or unsupported |
|---|---|
| "End-to-end encrypted messaging / chat / files" | The server side exists; the client is not shipped or verified here. Existing conversations will never be converted. Even then, only conversations created encrypted, and a hostile operator can still admit a new person (G1.6) |
| "We can't read your messages" | We can, for every plaintext conversation (host access). For an encrypted one we cannot read the text but see who, when and how big, and its reactions |
| "Zero-knowledge", "zero-access", "the operator can't see anything" | Category 2 is operator-readable; category 4 is infrastructure-visible; metadata is visible even for E2EE |
| "No logs", "we don't know when you're online" | Info-level logs record socket open and close per `user_id` with Docker timestamps; `last_seen_at` is stored (G5.3, G5.4) |
| "Anonymous", "untraceable", "metadata-free" | Cloudflare and the host see addresses; the membership graph, authors and timestamps are stored; an invite links a person to whoever invited them |
| "Your IP is hidden", "other members never see your IP" | Members learn the host's address. Other members not learning yours is by code reading only; no test exists. In a call the host sees every address |
| "Cloudflare can't see your traffic" | It terminates TLS and sees everything on the HTTP path |
| "Calls are always end-to-end encrypted", "video and screen share are end-to-end encrypted" | The server can force transport-only. Video sealing is unverified and the client's own `SECURITY.md` says it is not sealed |
| "Safety numbers / call codes guarantee nobody is listening" | They only help people who compare them |
| "Deleted means gone", "permanently erased" | Backups, WAL, other devices, Cloudflare and the Pocket ID account are not reached; `unlink` does not overwrite bytes |
| "We share no data with third parties" | Cloudflare, the hosting provider, ClamAV mirrors, GitHub, Wikipedia and a payment processor all see something |
| "Attachments are virus scanned" (for encrypted conversations) or "virus free" | Sealed files are not scanned by design (`a_sealed_upload_is_opaque_and_stored_as_it_came`) |
| "Encrypted reactions", "nobody can see who reacted" | Reactions are plaintext in v1, even in an encrypted conversation |
| "Secure encrypted backups", "deleted data is gone from backups" | `operator.sh backup` encrypts with age, but the tenant's key sits on the same host until moved, a backup also encrypted to the operator's key stays readable by the operator, nothing schedules or expires backups, and a restore brings back deleted accounts and messages (G5.10, N11). "Backups are encrypted with age" is true; the rest needs those caveats |
| "Legal hold preserves everything", "a hold freezes the community" | A hold keeps reports and blocks `operator.sh delete` and `restore`. Members can still delete messages and their accounts (G5.9, N12) |
| "Deleting a community erases it" | `operator.sh delete` removes volumes without shredding them and leaves the Cloudflare tunnel and outside backups (N14) |
| "Independently audited", "military grade", "unbreakable" | No independent review has happened ([`remaining-risks.md`](remaining-risks.md)) |
| "GDPR compliant", "DMCA compliant", "CALEA exempt", "outside US jurisdiction", "no KYC means we have no legal obligations", "E2EE means we cannot be ordered to do anything" | No legal conclusion is drawn anywhere here; [`compliance.md`](compliance.md) lists questions for counsel |
| "We never hand data to anyone" | The service must be able to act on valid legal process, abuse reports and suspension, and says so. `operator.sh export` and `backup` exist |
| "Bots can't see your messages" without qualification | True today of the bot API (G2.8); not a statement about the operator |
| "Unlimited" anything (storage, bandwidth, rooms) | There are caps and no quotas; neither is a promise ([`performance.md`](performance.md)) |
